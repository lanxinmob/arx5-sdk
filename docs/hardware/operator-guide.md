# ARX5 人类操作者手册

适用于已配置好的本机双臂工作台，面向遥操、示教、数据采集和模型试运行的操作者。第一次安装、更换机械臂或修改标定，请由技术维护者完成 [环境配置](setup.md)，再按本手册操作。

本文按 2026-10-12 的代码与已有操作记录整理；编写本手册时未新启动机械臂。下面的左右关系及参数只适用于这套设备。

## 先认识设备

| 设备 | 本机名称 | 日常用途 |
| --- | --- | --- |
| 左臂 | `X5 / can1` | 主臂：用手拖动，给右臂示教 |
| 右臂 | `X5_umi / can0` | 从臂：跟随左臂，执行和采集任务 |
| 腕部相机 | Vin 1 | 数据采集的默认相机 |
| Quest 默认左腕视角 | Vin 4 | 需要单独确认有没有实际画面 |
| SpaceMouse | 3Dconnexion 六轴鼠标 | 推拉、倾斜和旋转鼠标帽控制一臂 |

“回零 / home”是机械臂移到程序定义的关节零位，通常还会张开夹爪；不是原地停止，也不会自动避开桌面、物体或另一条臂。“阻尼”是减缓运动的状态，不是锁定位置或切断电源，机械臂仍可能下坠。

**已知现场问题：**2026-10-12 最近一次检查时，Vin 1 与 Vin 4 都只有无信号灰画面。采集前必须恢复输入并重新检查。夹爪闭合小缝和重复性也尚未完全解决；不能用程序显示“0 mm”代替观察实物。详见 [本机快照](current-machine.md)。

## 每次开始前

1. 确认机械臂底座固定、供电与线缆正常，知道硬急停在哪里、如何操作。拿开夹爪中的物品，清空两臂回零的整段路径。
2. 确认谁负责操作；不要让另一人同时启动控制程序。一次只选下面一种方式，不能在采集或遥操运行时再开标定、拖动或其他测试程序。
3. 确认当前确实是本机这两条臂，硬件未更换、标定未改变。换臂或夹爪后停止套用本文数值，请维护者重新确认。
4. 有漂移风险时先安排可靠支撑。操作中身体、衣物与线缆避开关节和夹爪夹点；跟随期间不要用手纠正从臂位置。
5. 打开终端，完成下面检查，再选择具体操作方式。需要第二个终端时，也执行前两行。

```bash
conda activate arx5
cd /home/hjadmin/projects/arx5-sdk/python
python -B -c 'import arx5_interface as s; print(s.__file__)'
ip -brief link show can0
ip -brief link show can1
pgrep -af 'zmq_.*server|vr_joint_bridge|spacemouse|leader_follower|record_episodes|drag_mode'
```

应看到 SDK 路径位于本仓库 `python/`，两个 CAN 接口为 `UP`。最后一条会列出可能正在运行的控制程序；若看见旧程序或不认识的进程，先找运行者确认，不能再开一份。这些检查不启动电机控制；后文的正式启动命令会连接电机，有些会立即回零。

`conda` 不存在、环境不存在、CAN 缺失或接口未启用时，停在此处，按 [排障手册](troubleshooting.md) 请维护者处理。已有本机配置无需每次重装依赖或重新启动 CAN 服务。

## 选择操作方式

| 目的 | 本页章节 | 启动后什么时候运动 |
| --- | --- | --- |
| 拖动左臂，让右臂跟随 | [主从遥操](#leader-follower) | 启动先两臂回零；按空格才开始跟随 |
| 保存带图像和语言指令的示教数据 | [采集数据](#recording) | 相机检查通过后两臂回零；输入 r 回车后先对齐再采集 |
| 用六轴鼠标控制右臂 | [SpaceMouse](#spacemouse) | 启动立即回零；双按钮再次回零 |
| 用 Quest 手柄控制双臂 | [Quest](#quest) | 收到两手有效数据后自动两臂回零 |
| 只调整一臂位置、自由拖动 | [自由拖动](#drag) | 启动先回零，再进入拖动模式 |
| 让策略模型执行任务 | [模型试运行](#model) | 取决于模型程序；须先拿到该模型的操作单 |

<a id="leader-follower"></a>
## 主从遥操

在桌面终端运行：

```bash
python examples/leader_follower_teleop.py X5 can1 X5_umi can0 \
  -g -3.2969 --follower-gripper-open-readout -3.45369 \
  --leader-gravity-scale 1.2 --follower-gravity-scale 1.0 \
  --gripper-close-threshold 0.001 --diagnostics
```

1. 两臂会先依次回零；保持路径空闲，等它们实际停止并到位。
2. 左臂可用手轻轻拖动，右臂暂时保持位置。先调整到适合示教的姿态。
3. 按一下空格开始跟随，小幅移动左臂，确认右臂跟随方向及夹爪动作正确。开始跟随可能让右臂向左臂对应姿态运动，两臂起始姿态不要差得过大。
4. 暂停时按空格；正常结束按小写 `q` 或在终端按 Ctrl+C，等待回零与程序退出。

| 按键 | 作用 |
| --- | --- |
| 空格 | 开始 / 暂停跟随 |
| `h` | 两臂回零，再等待空格开始 |
| `q` 或 Ctrl+C | 正常退出，尝试两臂回零 |

这些是桌面键盘事件，**不需要回车**。暂停时右臂仍位置保持，不能当作可自由拖动；左臂有重力补偿也可能缓慢漂移。若明显下坠、上飘或夹爪受阻，停止操作，保留终端诊断输出交给维护者，不在运行中试调补偿或增益。

<a id="recording"></a>
## 采集数据

### 先确认相机

```bash
python examples/record_episodes.py --check-cameras --no-preview
```

此命令只检查相机，不连接机械臂。看到“相机画面检查通过”才进入下一步；灰屏、黑屏、`NO CAMERA SIGNAL` 或 `Cameras not delivering new frames` 时先检查相机供电、视频输出、线缆和采集卡输入。设备存在或显示“60 FPS”不表示已有有效图像。

正式采集窗口中还要检查物体和夹爪是否入镜、焦点是否清楚。相机检查不能替人判断构图。

### 启动与一轮采集

```bash
python examples/record_episodes.py X5 can1 X5_umi can0 \
  --dataset-dir data/demonstrations \
  -g -3.2969 --follower-gripper-open-readout -3.45369 \
  --leader-gravity-scale 1.2 --follower-gravity-scale 1.0
```

1. 相机和预览检查通过后，两臂同步回零，再都进入手动拖动状态。
2. 在终端输入任务，例如“把红色方块放进碗里”，回车。任务文字是数据标签，不会让机械臂自动执行。
3. 布置任务并调整两臂起始位置；输入 `r` 回车。此时右臂会先限速对齐左臂，保持左臂平稳，不要抢着开始任务。
4. 终端出现“正在采集”后，通过左臂示教。完成后在终端输入 `ok` 或 `f` 回车，按真实结果标记并保存。
5. 保存后两臂恢复手动拖动，右臂不再跟随。整理场景，按提示选择指令和开始下一轮。

| 状态 | 输入后回车 | 结果 |
| --- | --- | --- |
| 选择任务文字 | 文本，或历史编号如 `1` | 新任务或复用历史指令 |
| 等待开始 | `r` | 对齐后开始采集 |
| 等待开始 | `n` / `h` | 更换指令 / 两臂回零后恢复拖动 |
| 正在采集或等待结果 | `ok` | 标为成功，保存 |
| 正在采集或等待结果 | `f` | 标为失败，保存；不是丢弃 |
| 正在采集或等待结果 | `d` | 丢弃本轮，不作为完成的训练样本 |
| 任一交互阶段 | `q` | 退出；未完成轮次按中断保留 |

默认每轮 60 秒，到时停采并等待你填写结果；程序不会判断任务是否成功。这里的命令需要**回车**，也没有 `s` 保存键。

正常结束用 `q` 回车，等待两臂慢回零、文件写完和终端返回提示符。关闭预览窗口或在窗口按 Q/Esc 会中断当前轮并尝试回零；不要用关窗口代替成功保存。

数据位于 `python/data/demonstrations/`，默认文件为 `episode_000000.hdf5` 等，编号递增。`.partial.hdf5` 是尚未正常完成或被中断的数据；`.discarded.hdf5` 是丢弃数据，都会保留，不要手动改名当作成功样本。更多采集方式见 [完整采集手册](../../python/recording/README.md)。

<a id="spacemouse"></a>
## SpaceMouse 控制一臂

确认右臂没有其他控制程序，再运行：

```bash
python examples/spacemouse_teleop.py X5_umi can0 --gripper-open-readout -3.45369
```

若操作左臂，用下面命令替代，不能原样沿用右臂参数：

```bash
python examples/spacemouse_teleop.py X5 can1 --gripper-open-readout -3.2969
```

启动后先等回零，轻推/拉、倾斜/旋转鼠标帽控制末端。按钮 0 打开夹爪、按钮 1 闭合夹爪；设备按钮编号首次由维护者确认。**同时按两按钮是再次回零，不是停止。**正常退出在终端按 Ctrl+C，会尝试回零再进入阻尼。程序没有设备断流检查，鼠标失联不能当作已停止的保证。

末端目标不可达或超出关节限位时，程序提示并保持最后有效目标；向可达方向反向操作即可恢复，不需要重启。连续向限位外操作不会累计越界位移。

直连版启动和双按钮回零时夹爪全开，首次开始操控及回零后恢复操控都从全开目标开始；按按钮 1 才逐步闭合。需要保持某个开度时不要把回零当作普通暂停。

每轴平移速度设置为 10 cm/s；同时推动多个轴时，不能把 10 cm/s 当作合成速度上限。

<a id="quest"></a>
## Quest 双臂遥操

同样先由维护者确认两路服务的夹爪标定，再确认 Quest app 配置的电脑 Wi-Fi IP；历史地址是 `192.168.31.137`，实际地址可能变化。电脑终端可用 `ip -brief address` 查看，再选择与 Quest 同一 Wi-Fi 网段的地址。app 连接电脑端口 `10000`。

终端 1：

```bash
python communication/zmq_joint_server.py X5_umi can0 X5 can1 --port 8765 --port 8764
```

终端 2：

```bash
python communication/vr_joint_bridge.py --right-model X5_umi --left-model X5
```

先启动电脑程序，再打开或重新连接 Quest app。两手有效数据到达后，**两臂会自动回零并全开夹爪**；此时保持回零路径空闲，等实际到位后再小幅移动手柄。

| 操作 | 作用 |
| --- | --- |
| 移动 / 转动左右手柄 | 控制对应臂的末端 |
| 侧扳机 | 控制对应夹爪 |
| 右 A 长按约 1 秒 | 右臂慢回零，保持当前夹爪开度 |
| 左 X 长按约 1 秒 | 左臂慢回零，保持当前夹爪开度 |
| 终端 2 按 Ctrl+C | 结束遥操，尝试两臂慢回零，再请求阻尼 |

按钮复位依赖当前 app 的特殊数据格式；app 更新后需维护者重新验证。正常结束先退出终端 2，等两臂停止、退出完成，再退出终端 1。追踪失流或断连也可能触发回零；不能靠关 app 保证原地停止。

默认窗口显示 iPhUMI 手机主视角、左腕、右腕；iPhone 要解锁、信任电脑并在 iPhUMI 选择 Deployment USB streaming。**关闭 Quest 预览窗口不会停止机械臂遥操。**这与数据采集窗口不同。

需要保存预览视频时，在终端 2 的命令末尾加 `--record-video`，默认 MP4 写入 `~/Videos/arx5/`；这只是窗口合成视频，不是前文的示教训练数据。没有桌面时可加 `--no-preview`，但不能同时录制该窗口视频。

<a id="drag"></a>
## 单臂自由拖动

```bash
python examples/drag_mode.py X5_umi can0 -g -3.45369
```

启动先回零，再轻轻用手调整右臂。空格切换“自由拖动 / 位置保持”，`h` 回零后恢复拖动，`q` 正常回零退出，不需回车。不要对位置保持中的机械臂用力拖动。退出后不能假定机械臂仍保持空中姿态，要确认支撑；如果明显漂移，停止并让维护者检查负载和补偿。

<a id="model"></a>
## 策略模型试运行

模型之间没有统一的启动命令和停止键。试运行前，请维护者提供该模型的操作单，至少包含：三个进程（模型服务、机器人服务、操作客户端）的启动顺序与命令、实际控制哪条臂、启动是否回零、相机需求、开始/暂停/退出方法、断流后的行为以及数据保存位置。

先用空载小幅动作验证方向与夹爪，再放入任务物体，始终有人看护。界面出现 `shadow`、`dry-run` 或“仅观察”字样时，也要确认是否仍有启动回零；有的模型客户端在观察模式下也会移动机械臂。首次接新模型的技术步骤见 [模型接入手册](model-integration.md)，不能靠本页的通用命令代替该模型的适配与验收。

## 什么时候停止，怎样退出

**有碰撞、夹人或失控风险：**使用现场硬件急停，人员避开运动区域；不要等待终端命令、程序超时或回零完成。急停后按现场恢复流程处理，不立即重启程序继续任务。

**没有即时危险、正常收工：**按你当前模式的退出键一次，留出回零路径，观察机械臂实际停止，等文件写完、程序退出，再确认稳定支撑并按现场流程关闭设备。不要通过拔 USB、拔 CAN 或强制杀进程来正常退出；也不要连续按 Ctrl+C 催促回零，采集程序在恢复期间不会用重复 Ctrl+C 取消回零。

| 现象 | 操作者先做什么 |
| --- | --- |
| 手臂突然下坠、抖动、撞物或动作反向 | 停止输入；有即时风险用硬急停。记录所用模式及终端报错，请维护者检查 |
| `Emergency latched` / `Over current` | 停止任务并处理支撑，保留最早错误；排除原因后由维护者重启，不能继续按回零键清故障 |
| 夹爪到 0 但还有缝，或夹住物体后不继续闭合 | 停止硬压，记录实物情况及日志；可能涉及零点、传动或接触保持，不自行提高力度 |
| 相机黑/灰屏、`NO CAMERA SIGNAL` | 不开始采集/依赖视觉的模型任务；检查输入并联系维护者 |
| 预览冻结、采集中报错 | 停止任务；若程序已在恢复，观察其回零结果，保留数据和错误 |
| 程序称已回零，但臂仍未到位 | 视为未完成；确认路径和支撑，请维护者查反馈，不反复重试 |
| 不确定当前哪个程序还在控制 | 不再开新程序，用开机检查命令查进程，找运行者确认 |

停止、阻尼和回零的完整差异见 [退出行为表](operations.md#lifecycle)。电机断电、硬急停、线缆断开或进程崩溃时，软件不能保证回零。

## 收工交接

记录日期、使用方式和命令、任务结果、数据/视频目录、是否正常退出、机械臂最后姿态以及任何异常。采集数据不要因报错直接删除，保留原文件交给维护者判定。首次错误优先保存终端文字；能安全拍照时可补充实物情况。带着这些信息查 [故障排查](troubleshooting.md)，更容易确认下一步。
